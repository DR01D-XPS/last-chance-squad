# Исходники, экспорт и импорт

`src/art.js` — единый источник палитры, геометрии и семи анимационных состояний. Canvas-предпросмотр и SVG-экспорт используют одинаковые команды рисования. PNG получаются из SVG в локальном Chromium/Edge. Генеративные растровые изображения в игровом наборе не используются.

## Состав

| Путь | Содержимое |
| --- | --- |
| `assets/source/art-direction.svg` | редактируемый лист стиля 1600 × 1050 |
| `assets/source/characters/` | четыре SVG-листа и отдельные SVG-позы |
| `assets/sprites/characters/player-1…4.png` | четыре прозрачных листа 1024 × 896 |
| `assets/sprites/props.png` | предметы, восемь ячеек 128 × 128, лист 512 × 256 |
| `assets/sprites/weapons.png` | ракетница, гарпун, дробовик, лист 384 × 128 |
| `assets/sprites/modules/` | фасады, платформы, лавка, рулетка, флаги |
| `assets/sprites/backgrounds/` | три фона 1600 × 800 |
| `assets/previews/` | лист стиля, карта города, три арены |
| `assets/manifest.json` | палитра, последовательность кадров, длительности и точки крепления |
| `references/` | предоставленные пользователем материалы, отдельно от оригинальных ассетов |

Каждый лист персонажа содержит 7 строк сверху вниз: `idle`, `walk`, `aim`, `hurt`, `blast`, `joy`, `roulette_loss`. В строке 8 кадров слева направо. Зацикленные состояния экспортируются с фазами 0…7/8, однократные — 0…1, чтобы включить конечную позу.

Ячейка 128 × 128, опорная точка ног `(64,114)` от верхнего левого угла. Нормализованная точка Unity от нижнего левого угла — `(0.5,0.109375)`. Точки корпуса, глаз, шапки, рук и оружия записаны в манифесте. Форму коллайдера не брать автоматически из каждой деформированной позы.

## Импорт в Unity

Это комплект ассетов, а не настроенный Unity-проект. Unity Editor в текущей рабочей среде не обнаружен; импорт и итоговый Player ещё не проверены.

1. Скопировать `assets/sprites` и `assets/manifest.json` в `Assets/LastChance/Art/` существующего проекта.
2. Для PNG персонажей установить `Texture Type: Sprite (2D and UI)`, `Sprite Mode: Multiple`, `Pixels Per Unit: 48`, `Filter Mode: Bilinear`, `Wrap Mode: Clamp`, `Generate Mip Maps: Off`, альфа из исходника. Для первого визуального сравнения отключить компрессию и оставить максимальный размер не меньше 1024.
3. В Sprite Editor разрезать лист по `Grid By Cell Size`, ячейка 128 × 128. Всем кадрам задать `Custom Pivot: (0.5, 0.109375)` и `Mesh Type: Full Rect`. Использовать стабильные имена `player-1_idle_00`…`player-1_roulette_loss_07`; порядок задаёт манифест, а не случайный порядок результата нарезки.
4. Создать семь клипов. Длительность и зацикливание взять из манифеста. Например, ожидание содержит восемь кадров за 1,2 с, урон — восемь за 0,24 с. Для всех костюмов используются одна структура состояний и одинаковые переходы; меняются ссылки на кадры или Sprite Library.
5. Оружие импортировать отдельными спрайтами. Точка хвата находится в `(48,64)` каждой 128-px ячейки, то есть нормализованно `(0.375,0.5)`. Вращение задаёт направление прицела, а не мобильность персонажа.
6. Предметы нарезать ячейками 128 × 128, опорная точка `(0.5,0.5)`. Фасады и флаги импортировать отдельными спрайтами с точками из `modules` манифеста. Видимая верхняя поверхность платформы находится на 12 px от верха PNG; коллайдер совмещать с ней.
7. Для физики тела и добычи использовать только 2D-компоненты. У персонажа отдельный постоянный коллайдер около 48 × 78 px. Визуальное растяжение не изменяет массу, коллайдер, дальность взаимодействия или расход мобильности.
8. Сгруппировать игровые PNG в атласы, исключить крупные фоны из атласа персонажей. Настроить слои отрисовки по `ART_DIRECTION.md`. Повторить замер в собранном Windows Player на целевом компьютере.

Вход из комнаты, загрузка и смена костюма не должны переключать логику движения. Рюкзак и шапка — визуальные варианты. В первой итерации лист содержит готовые композиции; геометрия исходника позволяет позже выделить слои для костей или покадровых замен без изменения дизайна.

## Воспроизводимый экспорт

```powershell
npm ci
npm run export
npm test
python tools/verify-assets.py
npm run verify
```

Экспорт использует установленный Microsoft Edge или Google Chrome. Если они отсутствуют, можно установить Chromium командой `npx playwright install chromium`, затем повторить экспорт. Для PNG-проверки нужны Python и Pillow (`python -m pip install Pillow`). Браузер нужен для инструментов экспорта и проверки; локальный просмотр готовой сцены не требует npm или сервера.

После изменения формы, размеров или анимации экспортировать весь комплект, проверить все 224 кадра и визуально посмотреть лист стиля и три арены. После изменения отрисовки, физики или эффектов повторить замер нагрузки. Менять численные параметры в `src/simulation.js`, а визуальные — в `src/art.js`; не зашивать стоимость движения в анимацию.
